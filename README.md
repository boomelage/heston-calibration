# Heston (1993) stochastic volatility parameter calibration

This repository has quite convoluted logic at the moment and relies a bit too much on storing various files as csvs which makes the workflow less intuitive

**How to use:**

1. Ensure the correct format of CBOE trades data is present in [`data/options/raw`](data/options/raw)
2. Ensure you have the same format of dividend and interest rates as present in [`data/market/`](data/market/). Namely, [`historical_SPX_ivols.csv`](data/market/historical_SPX_ivols.csv) and [`historical_USGG12M.csv`](data/market/historical_USGG12M.csv). These two file names are hard-coded into the logic of [`get_rg.py`](data/get_rg.py) so the filenames must match.
3. Run [`calibrator_prototype.py`](src/calibrator_prototype.py) to calibrate once per trading day (over a pooled, moneyness-normalised surface) using the calibration engine [`calibrate_heston.py`](src/calibrate_heston.py). It reads the raw trades directly and does the OTM cleaning in-memory (via `_utils._prepare_options`), so there is no separate extraction step. A **Bates (1996)** variant (Heston stochastic vol + Merton jumps, engine [`calibrate_bates.py`](src/calibrate_bates.py)) is selectable with `--MODEL bates` (default `heston`). Outputs are namespaced by model and objective under `results/<model>/calibrations/<objective>/` (`<model>` = `heston`, the default, or `bates`; `<objective>` = `vol`, the default, or `price` via `--OBJECTIVE`). Optionally run [`validate_calibrations.py`](src/results/validate_calibrations.py) to grade the results.

All model/calibration constants (surface coverage knobs, the box bounds, the acceptance gate, the OTM cutoff, the seed grid) live in one place: [`src/config.py`](src/config.py).

The downstream figure/table scripts live under [`src/results/`](src/results/) (`surfaces/{make_surface,plot_surfaces}.py`, `smiles/smiles.py`, `tables/objective_comparison.py`), alongside the two read-only graders `validate_calibrations.py` and `wing_residuals.py`. They read calibrations from and write figures into the repo-level `results/` tree, and share the QuantLib helpers in [`src/_utils.py`](src/_utils.py).

As you can see the whole setup is quite dependent on a rather convoluted file structure with very specific data formats and the way the data is called in [`calibrator_prototype.py`](src/calibrator_prototype.py) is through hardcoded calls to dataframe column names.

## Data files are not tracked in git

The bulky per-day option data is **deliberately excluded from version control** (see [`.gitignore`](.gitignore)):

- `data/options/raw/` — raw CBOE trade files (`UnderlyingOptionsTradesCalcs_*.csv`), ~80–90 MB per
  trading day. These sit just under GitHub's hard 100 MB-per-file push limit and would blow the
  repository's size budget within a few days, so they are never committed.
- `results/heston/calibrations/<objective>/calibration_tests/` — per-day repricing diagnostics (one file per
  trading day), which accumulate as years of data are added. Regenerated by the calibrator, so not committed.

Each folder keeps only a `.gitkeep` so the path exists on a fresh clone. Only the small derived
artefacts stay tracked: the `{calibrations,rejections,validation}.csv` triple for the default `vol`
objective (`results/heston/calibrations/vol/`) and the market rates in `data/market/`. The `price` objective
is still selectable via `--OBJECTIVE price`, but its outputs are not committed on this branch.

**To run the pipeline on a fresh clone**, supply the inputs yourself:

1. Drop your CBOE `UnderlyingOptionsTradesCalcs_*.csv` files into `data/options/raw/`.
2. Run `python src/calibrator_prototype.py` (and optionally `python src/results/validate_calibrations.py`). The calibrator reads `raw/` directly and cleans to OTM in-memory; no extraction step is needed.
